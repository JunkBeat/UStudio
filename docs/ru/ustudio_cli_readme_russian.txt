================================================================================
UStudio — консольный режим (CLI): справочник
================================================================================

Запуск:
    ustudio_cli <команда> [параметры]

Справка по любой команде:
    ustudio_cli help export
    ustudio_cli export --help

--------------------------------------------------------------------------------
БЫСТРЫЙ СТАРТ
--------------------------------------------------------------------------------

    # Отобразить в консоли первые 10 объектов AudioClip
    ustudio_cli list -F data.unity3d --type AudioClip --limit 10

    # Экспортировать все текстуры игры в папку ./textures
    ustudio_cli export -p "Game_Data" --type Texture2D -o ./textures

    # Изучить содержимое одного объекта
    ustudio_cli inspect -F data.unity3d level0:1

    # Экспорт -> правка -> импорт (с сохранением результата в ./output)
    ustudio_cli export -F data.unity3d --id level0:1 --mode json -o ./patch
    (отредактируйте файл из ./patch в любом текстовом редакторе)
    ustudio_cli import -F data.unity3d ./patch --save-as ./output

Оригинальные файлы при этом не затрагиваются: --save-as всегда пишет в новую папку.

--------------------------------------------------------------------------------
1. ДВА РЕЖИМА РАБОТЫ
--------------------------------------------------------------------------------

Одиночная команда — загружает данные, выполняет одно действие и завершается.
Удобно для скриптов:

    ustudio_cli list -F data.unity3d --type AudioClip

Интерактивная оболочка (shell) — загружает данные ОДИН РАЗ, после чего можно
выполнять любое число команд без повторной загрузки. Для больших файлов это
заметно быстрее: в одиночном режиме загрузка повторяется при каждой команде.

    ustudio_cli shell -F data.unity3d
    ustudio [data.unity3d]> list --type Texture2D --limit 5
    ustudio [data.unity3d]> inspect level0:1 --dump typed
    ustudio [data.unity3d]> exit

В оболочке работают те же команды, но без параметров загрузки, т.к. данные уже загружены.
Справка в оболочке: `help <команда>` (флаг --help там не используется).

--------------------------------------------------------------------------------
2. ОБЩИЕ ПРАВИЛА
--------------------------------------------------------------------------------

ВЫВОД
  Результат команды (таблица, JSON, CSV, дамп объекта) идёт в stdout — его
  можно перенаправить в файл или передать другой программе:
      ustudio_cli list -F data.unity3d --format json > result.json
  Прогресс, предупреждения и сообщения об ошибках идут в stderr и в результат
  не попадают. Флаг -q (--quiet) убирает индикатор прогресса.
  Если вывод перенаправлен (в файл или в другую программу), он всегда в UTF-8,
  какая бы кодовая страница ни была у консоли.
  Флаг -v (--verbose) указывается ПЕРЕД командой и включает подробности:
  полный текст ошибок и примечания генератора SDF-шрифтов:
      ustudio_cli -v import -F data.unity3d ./patch

КОДЫ ВОЗВРАТА
  0 — успех (в том числе если часть объектов пропущена по ожидаемой причине,
      например пустая текстура при экспорте);
  1 — ошибка выполнения (ничего не загружено, объект не найден, ссылка
      неоднозначна, хотя бы одна правка import не применилась и т. п.), текст
      ошибки — в stderr (если не применилась только часть правок и нет --strict,
      остальные при этом сохраняются);
  2 — неверные аргументы командной строки.

ССЫЛКА НА ОБЪЕКТ
  PATH_ID уникален только внутри одного файла: один и тот же PATH_ID может
  встречаться во многих файлах. Поэтому ссылка бывает трёх видов:
      1                       — PATH_ID, если он есть ровно в одном файле;
      level0:1                — SOURCE:PATH_ID, то есть «файл:PATH_ID»;
      GameB/Data/level0:1     — если одноимённые файлы лежат в разных папках
                                (несколько игр): добавьте часть пути перед
                                именем файла (регистр не важен).
  Если ссылка неоднозначна, команда завершится с ошибкой и покажет все
  подходящие файлы — «первый попавшийся» она никогда не берёт.

--------------------------------------------------------------------------------
3. ПАРАМЕТРЫ ЗАГРУЗКИ
--------------------------------------------------------------------------------

Общие для команд load, shell, list, inspect, export, import, save.

  -p, --folder ПУТЬ
      Загрузить папку целиком.
          ustudio_cli list -p "C:\Games\MyGame\MyGame_Data" --type Font
      Игру для macOS загружайте, указав папку приложения (X.app):
          ustudio_cli list -p "MyGame.app" --type Font
      Файлы Nintendo Switch игры нужно сначала распаковать другой программой, затем укажите папку распакованной игры:
          ustudio_cli list -p "C:\Games\KAMIKO" --type Font

  -F, --files ПУТЬ
      Загрузить конкретный файл. Можно повторять: -F level0 -F level1.
      Нельзя сочетать с -p.

  Если не указан ни -p, ни -F
      Команда ищет папку "*_Data" в ТЕКУЩЕЙ папке и загружает её (найденный
      путь выводится в stderr). Папка должна содержать данные Unity, а не
      просто называться "*_Data"; если подходящих папок нет или их несколько,
      команда сообщит об этом и ничего не выберет сама.
      Там, где команда может перезаписать оригиналы (import --in-place, save
      без --save-as, shell), -p или -F обязательны.

  -a, --all
      Загрузить объекты ВСЕХ типов. Без этого флага в списке появятся 
      только основные типы (текстуры, звуки, шрифты, MonoBehaviour, 
      GameObject и т. п.); например, объектов Transform не будет.

  -x, --exclude ПАПКА
      Пропустить указанную папку при загрузке папки целиком 
      (можно повторять несколько раз) — например, чтобы исключить из загрузки 
      папку с резервной копией игры внутри игровой папки.

  --deps ПАПКА
      Дополнительно искать зависимости в бандлах этой папки (можно повторять).
      Пригодится, если вы загружаете ОДИН бандл через -F, а его скрипты лежат в
      соседних бандлах (типично для Unity Addressables, папка
      StreamingAssets/aa/<Платформа>): без --deps имена скриптов будут
      "Unknown". Папка сканируется один раз перед загрузкой (быстро: читаются
      только заголовки). При загрузке папки целиком (-p) соседние бандлы
      находятся сами.
          Пример команды:
          ustudio_cli list -F "aa/StandaloneWindows64/localization_en_assets_all.bundle" --script StringTable --deps "aa/StandaloneWindows64"

  --assembly ПАПКА
      Указать путь к папке Managed (которая содержит DLL со скриптами) — по ней 
      определяются имена и типы полей MonoBehaviour. Обычно обнаруживается сама 
      рядом с папкой *_Data; укажите вручную, если файлы игры лежат отдельно или 
      вы собираетесь подгрузить сдампленные с помощью IL2CppDumper библиотеки.
          ustudio_cli inspect 179 -F "resources.assets" --assembly "Game_Data/Managed"

  -u, --fallback-version ВЕРСИЯ
      Указать версию Unity, которая будет использована, если у файла она не прописана
      или разработчик специально исказил шапку игровых файлов.
      Пример ввода: "2019.4.15f1"

  -k, --cn-key КЛЮЧ
      Указать 16-байтный ключ дешифрования AssetBundle для игр, созданных на 
      китайском юнити движке. Без брутфорса.

  -T, --threshold ЧИСЛО   (по умолчанию 2000000 <объектов>)
      Порог срабатывания предупреждения
  -L, --large continue
      Если в загружаемых данных больше объектов, чем порог, нужно подтверждение.
      В одиночном режиме подтверждение даёт флаг -L continue (без него команда
      завершится с ошибкой, а не будет ждать ввода); в shell будет задан вопрос
      "продолжить? y/n". Без -a при этом загружаются только основные типы;
      остальные объекты не читаются и при сохранении записываются без изменений.
          ustudio_cli export -p "Game_Data" --type AudioClip -L continue

  -c, --collision {keep_first,raise}   (по умолчанию keep_first)
      Что делать с файлами, имеющими одинаковые имена (например, два
      resources.assets в папке с несколькими играми). Все такие файлы
      загружаются в любом случае; ресурсы и ссылки между файлами берут ближайший
      к объекту файл. Параметр влияет только на поиск файла ИСКЛЮЧИТЕЛЬНО по имени
      (например "level0" без указания игры):
        keep_first — берётся первый найденный (по умолчанию);
        raise      — прервать загрузку при первом совпадении имён.

  -q, --quiet
      Не показывать индикатор прогресса.

4. КОМАНДЫ

--------------------------------------------------------------------------------
load — загрузить и завершиться
--------------------------------------------------------------------------------
Применяются только параметры загрузки. Удобно, чтобы проверить, что папка 
загружается.

    ustudio_cli load -p "Truck-kun_Data" --all

--------------------------------------------------------------------------------
shell — загрузить один раз и работать интерактивно
--------------------------------------------------------------------------------
Параметры загрузки, затем приглашение "ustudio [имя]>". Выход — exit или quit.

    ustudio_cli shell -p "Game_Data" --fallback-version 2021.3.0f1

--------------------------------------------------------------------------------
list — отобразить список объектов
--------------------------------------------------------------------------------
Параметры загрузки плюс:

  -t, --type ТИПЫ          Типы через запятую: "Texture2D" или
                            "Texture2D,AudioClip".
  -s, --script ИМЯ         m_ClassName скрипта (для MonoBehaviour).
                            Находит ВСЕ скрипты с таким именем; для конкретики 
                            укажите в формате "m_Namespace.m_ClassName".
  -n, --name-contains СТР  Подстрока в имени объекта (без учёта регистра).
  -S, --source ИМЯ         Точное имя файла (или записи бандла), например
                            "level0" или "sharedassets0.assets".
  -m, --modified           Отобразить только объекты с несохранёнными правками.
  -r, --sort КОЛОНКИ       Задать параметры сортировки (см. ниже).
  -f, --format {table,json,csv}   Формат вывода (по умолчанию table).
  -l, --limit ЧИСЛО        Ограничение на кол-во выводимых в консоли строк.
  -o, --out ФАЙЛ           Записать результат в файл вместо вывода на экран.
  --sdf                    Показать SDF-шрифты (см. ниже).

Сортировка -r/--sort. Колонки: path_id, name, type, script_name, source, size,
modified. По умолчанию — сортировка по возрастанию; "-" перед именем колонки — по
убыванию. Колонки через запятую задают приоритет (внутри равных значений первой
колонки работает вторая). Строки сравниваются без учёта регистра.
ВАЖНО: значение, начинающееся с "-", пишите через "=": --sort=-size
(а не --sort -size, иначе "-size" будет принят за отдельный флаг).

SDF-шрифты (--sdf). Отображает шрифты TextMeshPro (TMP_FontAsset) вместе с их
материалом, текстурой-атласом и исходным файлом шрифта. Фильтры -t/-s/-n/-S/-m/
-r при этом не работают, а -f/-l/-o работают. В таблице в заголовке каждого
шрифта в квадратных скобках указана ссылка SOURCE:PATH_ID — её нужно передавать
в `export --sdf --id`. Если материал или текстура не определились, вместо них
выводится причина.

Примеры:
    ustudio_cli list -F data.unity3d --type AudioClip --limit 10
    ustudio_cli list -F data.unity3d --script "PlayerController" --format json
    ustudio_cli list -F data.unity3d --name-contains "button" --type Sprite
    ustudio_cli list -F data.unity3d --modified

    # Сохранить список объектов в CSV файл:
    ustudio_cli list -p "Game_Data" --type Texture2D --format csv -o textures.csv

    # Отобразить список объектов с сортировкой по именам от А до Я:
    ustudio_cli list -F data.unity3d --sort name

    # Отобразить объекты с сортировкой по именам от Я до А (обратите 
    внимание на символ "="):
    ustudio_cli list -F data.unity3d --sort=-name

    # Сортировка сначала по типу (А-Я), внутри типа — по размеру (от большего к 
    меньшему):
    ustudio_cli list -F data.unity3d --sort=type,-size

    # Отобразить список всех SDF-шрифтов:
    ustudio_cli list -F data.unity3d --sdf

--------------------------------------------------------------------------------
inspect — изучить содержимое одного объекта
--------------------------------------------------------------------------------
Параметры загрузки плюс:

  ref                      Ссылка на объект: PATH_ID или SOURCE:PATH_ID.
  -S, --source ИМЯ         Файл, если PATH_ID есть в нескольких юнити архивах 
                           (вместо указания файла через двоеточие в ref).
  -d, --dump {typed,json,hex}   Формат отображения дампа (по умолчанию typed)
        typed — «Type Name = value», по строке на поле;
        json  — дамп в формате JSON;
        hex   — первые 4096 байт данных объекта в шестнадцатеричном виде.

Примеры:
    ustudio_cli inspect -F data.unity3d level0:1
    ustudio_cli inspect -F data.unity3d level0:1 --dump json
    ustudio_cli inspect -F data.unity3d 1 --source level0

    # Если PATH_ID есть в нескольких файлах, команда покажет все варианты:
    ustudio_cli inspect -F data.unity3d 1
      -> ошибка: PATH_ID 1 есть в нескольких файлах, уточните source:path_id

--------------------------------------------------------------------------------
export — экспорт объектов в папку
--------------------------------------------------------------------------------
Параметры загрузки, фильтры из list (-t/-s/-n/-S) плюс:

  -i, --id ССЫЛКА      Экспортировать ровно один объект по айди (вместо фильтров).
  -m, --mode {typed,raw,content-raw,json}   Режим экспорта (по умолчанию typed)
        typed        — обычный формат объекта: PNG для текстур, WAV для звука,
                       шрифт, текст и т. д.; если тип не поддерживает конвертацию,
                       он экспортируется как JSON дамп;
        json         — полный дамп полей (расширение - .dump.json);
        raw          — сырые байты объекта (расширение - .dump.bin);
        content-raw  — сырые байты необработанных данных объекта во внешнем ресурсе 
                       (например, пиксели текстуры из .resS)
                       (расширение - .resdata.bin).
  -o, --out ПАПКА      Куда сохранять (по умолчанию ./UStudio_Assets).
  -w, --overwrite      Перезаписывать существующие файлы.
  --strict             Вернуть ненулевой код, если хоть один объект не удалось
                       экспортировать (ожидаемые пропуски — пустая текстура,
                       звук без данных — ошибкой не считаются).
  --group-by {none,type,source}
        Раскладывать файлы по подпапкам внутри -o: none — всё в одну папку (по
        умолчанию), type — по типам (-o/Texture2D/), source — по файлам-
        источникам. Значение по умолчанию можно сохранить: `config set
        export_grouping type`.
  --sdf                Экспортировать SDF-шрифты целиком (MonoBehaviour,
                       материал, текстура и, если есть, референсный Font) по пути  
                       SDF/<имя_шрифта>/ внутри папки -o. При указании параметра
                       -i — экспортировать один SDF шрифт (нужна ссылка на
                       TMP_FontAsset; ссылку берите из результата вывода команды 
                       `list --sdf`), без указания -i — экспортировать все 
                       найденные SDF шрифты. Фильтры и параметр -m при этом не 
                       действуют. Компонент, который не удалось определить, 
                       пропускается с сообщением, остальные экспортируются.

Имена файлов имеют вид "{имя} #{path_id} ({source}).расширение" — по ним
команда import потом находит нужный объект. Не переименовывайте файлы.

Примеры:
    ustudio_cli export -F data.unity3d --type Texture2D -o ./textures
    ustudio_cli export -p "Game_Data" --type AudioClip --group-by source -o ./audio
    ustudio_cli export -F data.unity3d --id level0:1 --mode json -o ./dump
    ustudio_cli export -F data.unity3d --name-contains "logo" --type Texture2D,Sprite

    # Экспорт одного SDF-шрифта (с указанием ссылки на TMP_FontAsset из `list --sdf`):
    ustudio_cli export -F data.unity3d --sdf --id "sharedassets0.assets:2646" -o ./out

    # Экспорт всех SDF-шрифтов по пути SDF/<имя шрифта>/:
    ustudio_cli export -F data.unity3d --sdf -o ./out

--------------------------------------------------------------------------------
import — применить папку с патчами
--------------------------------------------------------------------------------
Берёт файлы из папки, находит по имени соответствующие объекты и заменяет их
содержимое. Имена файлов должны быть такими же как при экспорте:
"{имя} #{path_id} ({source}).расширение". Формат правки определяется
расширением:

    .dump.json     — поля объекта целиком (JSON дамп);
    .dump.bin      — сырые байты объекта (Raw дамп);
    .resdata.bin   — сырые байты внешнего ресурса объекта (Raw Content);
    .png           — картинка для Texture2D / Sprite;
    .wav           — звук для AudioClip;
    .mp4 / .webm   — видео для VideoClip;
    .ttf / .otf    — шрифт для Font;
    .txt / .json / .bin — содержимое TextAsset.

Если для одного объекта в папке лежит несколько файлов, они применяются в
порядке .dump.bin -> .dump.json -> .resdata.bin -> .png/.wav/... — то есть
отредактированный PNG или WAV побеждает «старые» дампы.

Патч, для которого в загруженных файлах нет объекта, молча не пропадает. Так
бывает после обновления игры, когда номера объектов сдвинулись. Команда пишет
по строке на каждый такой файл:

    unmatched: Имя #12345 (sharedassets1.assets).dump.bin: no object #12345 in 'sharedassets1.assets'
    1 patch file(s) matched no loaded object and will NOT be applied (...)

и считает их в итоге: «Applied 2/3 patch(es)» и «1 unmatched». Остальные
патчи при этом применяются. Если ни один файл не нашёл объект, команда
завершается с ошибкой. Со --strict при любом таком файле не применяется и не
сохраняется ничего (код возврата не ноль). В `--dry-run` строка
«DRY RUN - N match(es) would be applied» считает только найденные патчи.

Найденный объект сверяется с патчем по имени из имени файла. У MonoBehaviour
сравниваются и скрипт, и имя («Скрипт.Имя»): после обновления игры на старом
номере часто оказывается соседний объект с тем же скриптом. Если имя другое,
правка всё равно считается своей, когда это видно по самому дампу (.dump.json):
у объекта то имя, которое дала ему эта же правка (мод уже ставился), или тот же
GameObject. У объекта без имени («Скрипт.Unnamed») сверять нечего: такая правка
пропускается, если соседние по номеру правки того же файла уже не совпадают со
своими объектами (номера в файле сдвинулись). Пропущенные правки выводятся
строкой «skipped: …» с причиной; --force применяет их всё равно.

Если патч нашёл свой объект, но применить его не удалось (файл повреждён,
данные не подходят к объекту, ошибка кодирования), остальные патчи всё равно
применяются и сохраняются. В конце команда сообщает, сколько правок не
применилось, и завершается с кодом 1 (то, что применилось, уже сохранено). То
же касается SDF-шрифтов из sdf_map.txt, которые не удалось создать.
Нужно «всё или ничего» (скрипты, установщики модов)? Добавьте --strict: при
любом сбое не применяется и не сохраняется ничего.
Исключение, в том числе для --strict: данные внешних ресурсов AudioClip /
VideoClip (режим --res-mode original) записываются в файл .resource / .resS
сразу, ещё до сохранения. Если импорт отменён, такие файлы уже изменены;
сообщение об ошибке перечисляет их, а с --backup их исходное содержимое
сохранено в резервной копии.

Для .dump.bin проверяется, что данные вообще могут быть этим объектом: файл не
пуст, не обрезан, его устройство совпадает с устройством объекта, а у
MonoBehaviour ссылка на скрипт та же, что у объекта сейчас (иначе правка сделана
для другого скрипта или для другой версии игры). Полная проверка устройства
возможна, когда скрипты игры читаются (при загрузке всей папки); с --partial
проверяется только ссылка на скрипт.

Параметры загрузки плюс:

  ПАПКА                Папка с патч-файласм (обязательный аргумент). Проверяется ДО
                       загрузки: если в ней нет подходящих файлов, команда
                       сразу завершится с ошибкой.
  -d, --dry-run        Показать, что будет применено, ничего не меняя.
  --strict             «Всё или ничего» для скриптов и установщиков. Если хоть одна
                       правка не применилась, патч-файл не нашёл свой объект
                       (см. «unmatched» выше), правка пропущена из-за несовпадения
                       имени или скрипта или цель sdf_map.txt не нашла объекта,
                       команда завершается с кодом 1 и ничего не применяет и не
                       сохраняет. Без --strict применяется всё, что можно, а
                       сбои только перечисляются.
  --force              Применять и те правки, у которых имя или скрипт в имени
                       файла уже не совпадает с объектом (например, после
                       обновления игры PATH_ID мог перейти к другому объекту).
                       По умолчанию такие правки пропускаются.
  --partial            Загрузить не всю папку из -p, а только файлы, которые
                       прописаны в именах импортируемых патч-файлов. Это повысит
                       скорость иимпорта в больших папках. Работает только в
                       режиме одиночных команд и только с параметром -p. Если 
                       какой-то файл нельзя определить однозначно (его либо нет, 
                       либо есть несколько с одинаковыми именами — поможет 
                       параметр -x), команда сообщит причину и загрузит 
                       папку целиком. Скрипты игры при таком импорте не
                       читаются, поэтому у MonoBehaviour правка не
                       сверяется по имени скрипта (строка «script
                       unresolved»); .dump.bin сверяется только по ссылке
                       на скрипт.

  Текстуры:
  --tex-mode {match_original,manual}
        match_original — сохранить формат текстуры как есть (по умолчанию);
        manual         — задать формат через --tex-format.
  --tex-format ФОРМАТ  Формат для --tex-mode manual:
        без сжатия:                RGBA32 (с альфой), RGB24, Alpha8
        десктоп/консоли (BC/DXT):  DXT1 (без альфы), DXT3, DXT5, BC4, BC5, BC7
                                   (лучшее качество; только для Unity 5 и новее)
        мобильные игры:            ETC_RGB4, ETC2_RGB, ETC2_RGBA8, ASTC_RGBA_4x4 (качество
                                   выше), ASTC_RGBA_8x8 (размер меньше), ATC_RGB4, ATC_RGBA8
        Формат применяется, даже если не подходит целевой платформе игры (например,
        DXT на мобильной игре). Название формата пишите точно как в списке, с учётом регистра.
        Опечатка НЕ вызывает ошибку, формат текстуры просто останется прежним.
  --tex-quality {medium,high}   Больше ни на что не влияет: текстуры всегда сжимаются с лучшим
                                качеством. Оставлен, чтобы старые команды работали.

  Звук:
  --audio-quality ЧИСЛО    Качество кодирования, 0–100 (0 — обычное, 100 —
                           лучшее).

  Куда писать данные AudioClip / VideoClip (и других объектов с внешним
  ресурсом):
  --res-mode {original,custom_resource}
        original        — в исходный ресурс объекта (по умолчанию);
        custom_resource — в отдельный файл-ресурс рядом (имя задается — через
                          --res-name), чтобы исходный ресурс не рос при каждом
                          импорте.
  --res-name ИМЯ       Имя отдельного файла-ресурса (только с --res-mode custom_resource).
                       Файл появится на диске после сохранения.

  Видео:
  --transcode                          Перекодировать видео перед упаковкой (по умолчанию
                                       выключено: файл кладётся как есть).
  --transcode-to {original,h264,vp8}   Целевой формат; original — как у
                                       исходного клипа (с откатом до h264, выдав
                                       предупреждением).
  --transcode-quality ЧИСЛО   Качество конвертации от 0 до 100. 
                              Результат конвертации создаётся рядом с
                              патч-файлом и имеет суффикс "_transcoded".

  Значения по умолчанию для всех этих параметров хранятся в `config` (см.
  ниже), так что один раз настроив их, можно не указывать каждый раз.

  Сохранение результата:
  Правки применяются только в памяти процесса, поэтому в одиночном режиме без
  флагов ниже результат автоматически сохраняется в НОВУЮ папку
  ./UStudio_Packed (оригиналы не затрагиваются):
  -A, --save-as ПАПКА  Сохранить в эту ОТДЕЛЬНУЮ папку.
  --in-place           Перезаписать оригинальные файлы (папку игры нужно указать
                       явно через -p или -F).
  -b, --backup         Перед перезаписью создать резервную копию оригиналов
                      (новая копия создаётся при каждом сохранении). Если
                       не удастся (например, нет места на диске), оригиналы не
                       будут тронуты. 
                       В копию попадают только файлы, которые импорт
                       действительно меняет: изменяемый файл (.assets, архив)
                       и те .resource / .resS, в которые импорт записал
                       данные (они записываются сразу, до сохранения).
                       Остальные файлы-ресурсы не копируются. Копия каждого
                       файла — это его содержимое до первой записи.
                       С --save-as копия не делается (ничего не
                       перезаписывается): команда предупредит об этом.
  --backup-dir ПАПКА   Куда класть копии (включает --backup): сюда попадают и
                       копии архивов, и копии файлов-ресурсов. По умолчанию —
                       %LOCALAPPDATA%\UStudio\backups, вне папки игры, чтобы
                       копии не попадали в следующую загрузку.
  --backup-keep N      Сколько последних копий каждого файла хранить помимо
                       самой первой (по умолчанию 1). Первая копия — нетронутый
                       оригинал — хранится всегда; лишние промежуточные
                       удаляются, чтобы копии не копились.
  В shell автосохранения нет — сеанс продолжается, и сохранить можно позже
  командой save.

  Игры на Addressables (папка StreamingAssets\aa): в каталоге игры
  (catalog.json, catalog.bin или catalog.bundle) у бандла может быть
  записана контрольная сумма. Если она есть, игра не загрузит изменённый
  бандл со старой суммой. Поэтому при сохранении такого бандла каталог
  обновляется автоматически: с --in-place он перезаписывается вместе с
  бандлами (и попадает в резервную копию), с --save-as кладётся в ту же
  папку рядом с копиями. Копируя результат в игру, копируйте и каталог.

Примеры:
    # Посмотреть, что будет применено, ничего не меняя:
    ustudio_cli import -F data.unity3d ./edited --dry-run

    # Применить и сохранить в новую папку:
    ustudio_cli import -F data.unity3d ./edited --save-as ./output

    # Применить и перезаписать оригинал, сделав резервную копию:
    ustudio_cli import -F data.unity3d ./edited --in-place --backup

    # Импорт в большой папке: загрузить только нужные файлы
    ustudio_cli import -p "Game_Data" ./edited --partial --save-as ./output

    # Текстуры: перекодировать в BC7
    ustudio_cli import -F data.unity3d ./textures --tex-mode manual --tex-format BC7 --save-as ./output

    # Импорт аудио с высоким качеством, запись данных — в отдельный файл-ресурс
    ustudio_cli import -F data.unity3d ./audio --audio-quality 90 --res-mode custom_resource --res-name my_audio.resource --save-as ./output

    # Пропускать «сомнительные» правки (по умолчанию) или всё-таки применить их
    ustudio_cli import -F data.unity3d ./edited --dry-run
    ustudio_cli import -F data.unity3d ./edited --force --save-as ./output


--------------------------------------------------------------------------------
save — сохранить изменённые файлы на диск
--------------------------------------------------------------------------------
Параметры загрузки плюс:

  -A, --save-as ПАПКА  Сохранить в НОВУЮ папку (оригиналы не будут затронуты). Без
                       этого флага оригиналы перезаписываются.
  -d, --dry-run        Показать, что было бы записано, ничего не записывая.
  -b, --backup, --backup-dir ПАПКА, --backup-keep N
                       Заранее создавать резервные копии оригиналов — так же, 
                       как у команды import.

Если изменённых объектов нет, команда завершится с ошибкой ("nothing modified").
В одиночном режиме объекты патчатся при помощи команды import, поэтому
отдельная команда save чаще нужна в shell:

    ustudio [data.unity3d]> import ./edited
    ustudio [data.unity3d]> list --modified
    ustudio [data.unity3d]> save --save-as ./output

После перезаписи оригиналов на месте (без --save-as) загруженные файлы
закрываются, и для продолжения работы в shell нужно загрузить данные заново.

--------------------------------------------------------------------------------
Генерация SDF-шрифтов (файл sdf_map.txt) — ЭКСПЕРИМЕНТАЛЬНО
--------------------------------------------------------------------------------
Отдельной команды нет: если в папке правок для import (в том числе во вложенных
папках) лежит файл sdf_map.txt, то после обычных правок import создаёт для
описанных в нём шрифтов TextMeshPro (TMP_FontAsset) новые глифы из указанного
.ttf/.otf. Обычных файлов правок в этой папке не требуется — достаточно
sdf_map.txt и шрифтов.

Функция экспериментальная: перед перезаписью оригиналов проверьте результат
через --dry-run и/или --save-as во временную папку.

    ustudio_cli import -F data.unity3d ./sdf_patches --dry-run
    ustudio_cli import -F data.unity3d ./sdf_patches --save-as ./output

--dry-run выводит план ("SDF <ссылка> 'имя' <- шрифт (mode=..., size=...,
range=..., N chars)"), ничего не генерируя. Во время работы для каждого шрифта
выводится одна строка:
    [1/2] ok: resources.assets:539 'LiberationSans SDF': added 182/183
Для отображения примечаний генератора нужен флаг -v.

Подробное описание формата sdf_map.txt (все настройки, как записывать символы, примеры)
лежит в файле sdf_map.md. Здесь же только то, что относится к запуску из командной строки. 

Короткий пример sdf_map.txt:
    "Arial SDF", "Other SDF" = font.ttf
    "Pixel SDF" = pixel.ttf, mode=full, size=fit, chars="ABCabc"

Откуда берутся символы (по порядку): chars= в строке -> chars= в строке
"default:" -> файл chars.txt рядом с sdf_map.txt. Если нет ни одного — выдаётся ошибка с
указанием строки.

Строка "default:" (не более одной, в любом месте) задаёт значения для всех строк,
где они не указаны. size, match_height, range, atlas и add_chars из неё
применяются только к строкам с итоговым режимом full.
Будет считаться за ошибку только если эти настройки написаны прямо в строке с 
режимом add/replace. Порядок приоритета: строка шрифта -> "default:" -> встроенные значения
(mode=add, размер и резкость как у самого шрифта, match_height=on, add_chars=on).

Относительные пути (шрифт, файл символов) отсчитываются от папки sdf_map.txt,
поэтому карту со шрифтами можно переносить одной папкой.

Один и тот же шрифт в двух строках с разными настройками — всегда выдаётся ошибка
с перечислением всех конфликтов. Цель, которая ничего не нашла, даёт
предупреждение (со --strict — ошибку). Параметр --partial в сочетании с sdf_map.txt
загружает всю папку целиком (т.к. карта может содержать имена SDF, которые находятся
неизвестно в каком файле).

--------------------------------------------------------------------------------
cab — работа с одним юнити архивом напрямую
--------------------------------------------------------------------------------
Команда cab не использует параметры загрузки: у каждой подкоманды свой флаг
-b/--bundle (в одиночном режиме) либо сначала выполняется `cab open` (в shell).

  cab open ПУТЬ
      Открыть бандл. В shell после этого можно вызывать list/view/export/rebuild
      без указания бандла.

  cab list [-b БАНДЛ] [-f {table,json}] [-l ЧИСЛО]
      Отобразить внутренние записи бандла: имя, размер, количество объектов.

  cab view [-b БАНДЛ] -e ЗАПИСЬ
      Разобрать одну запись и показать её объекты MonoBehaviour таблицей.

  cab export [-b БАНДЛ] [-e ЗАПИСЬ] [-o ПАПКА] [-q]
      Сохранить одну запись (сырые байты) или, если -e не указан, ВСЕ записи
      бандла. -o по умолчанию ./UStudio_Assets.

  cab rebuild [-b БАНДЛ] -o ФАЙЛ [--from-folder ПАПКА] [--set ЗАПИСЬ=ПУТЬ ...]
              [--mode {memory,disk}] [--packer {none,lz4,lz4hc,lzma,original}] [-q]
      Собрать бандл заново, подставив новые файлы вместо указанных записей
      (бандл всегда собирается целиком — так устроен формат):
        --from-folder ПАПКА — сопоставить файлы в папке с записями по имени
                              файла;
        --set ЗАПИСЬ=ПУТЬ   — заменить одну запись (можно повторять; применяется
                              после --from-folder и может переопределить его);
        --mode disk         — пересобрать на физическом накопителе, используется 
                              по умолчанию: сборку можно прервать (Ctrl+C);
        --mode memory       — пересобрать в памяти. Быстрее, но прервать сборку нельзя;
        --packer            — метод сжатия (original — как у исходного бандла).

Примеры:
    ustudio_cli cab list --bundle data.unity3d --limit 10
    ustudio_cli cab view --bundle data.unity3d --entry level0
    ustudio_cli cab export --bundle data.unity3d --entry level0 -o ./out
    ustudio_cli cab export --bundle data.unity3d -o ./all_entries
    ustudio_cli cab rebuild --bundle data.unity3d --set level0=./new_level0 -o ./rebuilt.unity3d
    ustudio_cli cab rebuild --bundle data.unity3d --from-folder ./edited_entries -o ./rebuilt.unity3d --packer lz4

--------------------------------------------------------------------------------
backup — создать резервные копии оригиналов
--------------------------------------------------------------------------------
Копии создаются флагом --backup (или --backup-dir) при перезаписи оригиналов
(save, import --in-place). Команды ниже игру не загружают.

  backup list [--game ИМЯ] [--backup-dir ПАПКА]
      Отобразить все созданные копии: папка, дата, файлы, размер и общий объём. 
      В квадратных скобках перечисляются игра и её версия на момент создания бэкапа, 
      если удалось определить. Параметр --game оставляет в выводе бэкапы одной 
      конкретной игры (вводится часть названия, без учёта регистра); точные
      названия игр для параметра --game вы можете посмотреть в выводе `backup list`.

  backup restore [ПАПКА_КОПИИ] [-f ИМЯ]... [--copy ДАТА] [--game ИМЯ] [-d]
                 [--relocate СТАРАЯ=НОВАЯ]... [--backup-dir ПАПКА]
      Возвращает файлы на их прежние места. Без указания ПАПКА_КОПИИ для каждого файла
      берётся самая СТАРАЯ копия — нетронутый оригинал; с ПАПКА_КОПИИ —
      файлы только этой копии.
        -f, --file ИМЯ   восстановить только этот файл (имя или полный путь;
                         можно повторять);
        --copy ДАТА      брать не самую старую, а самую новую копию, сделанную в
                         это время ("2026-09-24" или "2026-09-24 19:32");
        --game ИМЯ       восстановить только копии конкретной игры;
        -d, --dry-run    показать, что будет восстановлено, ничего не меняя;
        --relocate СТАРАЯ=НОВАЯ
                         игру перенесли: восстанавливать в папку НОВАЯ вместо
                         СТАРАЯ (СТАРАЯ — путь так, как его показывает
                         `backup list`; можно повторять).
      Перед заменой текущие файлы сами копируются в новую резервную копию —
      чтобы восстановление тоже можно было отменить в дальнейшем. Файл 
      записывается рядом и подменяется целиком, поэтому сбой не оставит наполовину 
      записанный файл; файл, занятый другой программой, выдаст ошибку.

      Файл, чья папка больше не существует (например, игру перенесли),
      не восстанавливается: команда ничего не меняет и подсказывает про
      --relocate. Старая папка заново не создаётся, чтобы файл не оказался не там,
      где игра лежит сейчас.

      Если короткое имя (-f resources.assets) есть в копиях нескольких игр, команда
      откажется угадывать и покажет доступные варианты: укажите полный путь к файлу или
      добавьте --game.

      ВАЖНО: копия — это файл на момент резервирования. Если игра после этого
      автоматически обновится, оригинал в резервной копии уже будет неактуальным.
      Отличить обновление игры от ваших правок нельзя. Вы также можете перепроверить 
      версию игры резервных копий, вызвав команду `backup list`.

Примеры:
    # Отобразить все копии и их вес:
    ustudio_cli backup list

    # Отобразить копии одной конкретной игры:
    ustudio_cli backup list --game Petscop

    # Сделать копию при перезаписи, затем при необходимости вернуть оригиналы:
    ustudio_cli import -F data.unity3d ./edited --in-place --backup
    ustudio_cli backup restore

    # Сначала посмотреть, что будет восстановлено:
    ustudio_cli backup restore --dry-run

    # Восстановить один файл по имени:
    ustudio_cli backup restore -f resources.assets

    # Восстановить резервную копию для файла resources.assets, 
    # сделанная в определённый день:
    ustudio_cli backup restore -f resources.assets --copy 2026-09-24

    # Если файл с таким именем есть у нескольких игр — указать игру или путь:
    ustudio_cli backup restore -f resources.assets --game Petscop
    ustudio_cli backup restore -f "C:\Games\Petscop\Petscop_Data\resources.assets"

    # Вернуть все копии одной игры:
    ustudio_cli backup restore --game Petscop

    # Игру перенесли в другую папку: указать, куда восстанавливать:
    ustudio_cli backup restore --relocate "C:\Games\Petscop=D:\Games\Petscop"

    # Восстановить конкретную копию (папка взята из вывода `backup list`):
    ustudio_cli backup restore "C:\Users\me\AppData\Local\UStudio\backups\2026-09-24_19-32-01"

  config get [КЛЮЧ]        Показать значение ключа или все значения (JSON).

--------------------------------------------------------------------------------
5. СКВОЗНОЙ ПРИМЕР: экспорт -> правка -> импорт -> проверка
--------------------------------------------------------------------------------

    # 1. Экспортировать объект в JSON:
    ustudio_cli export -F data.unity3d --id level0:1 --mode json -o ./patch

    # 2. Отредактировать ./patch/logo #1 (level0).dump.json в любом текстовом
    #    редакторе — например, изменить значение "m_Name".

    # 3. Применить правку и сохранить результат в новую папку:
    ustudio_cli import -F data.unity3d ./patch --save-as ./output

    # 4. Проверить результат, изучив содержимое объекта в пропатченном файле:
    ustudio_cli inspect -F ./output/data.unity3d level0:1 --dump json

Оригинальный data.unity3d не изменился. Чтобы перезаписать оригинал, используйте
--in-place (лучше совместно с параметром --backup).

Тот же самый сценарий в интерактивной среде — без повторной загрузки на каждом шаге:

    ustudio_cli shell -F data.unity3d

    ustudio [data.unity3d]> export --id level0:1 --mode json -o ./patch
    (файл редактируется вне оболочки)
    ustudio [data.unity3d]> import ./patch
    ustudio [data.unity3d]> list --modified
    ustudio [data.unity3d]> save --save-as ./output
    ustudio [data.unity3d]> exit

Другие типичные сценарии:

    # Заменить текстуру: экспорт -> правка PNG -> импорт
    ustudio_cli export -F data.unity3d --name-contains "logo" --type Texture2D -o ./tex
    (отредактируйте PNG, не меняя имя файла)
    ustudio_cli import -F data.unity3d ./tex --save-as ./output

    # Заменить звук
    ustudio_cli export -F data.unity3d --type AudioClip --name-contains "click" -o ./snd
    (замените WAV своим файлом, не меняя имя)
    ustudio_cli import -F data.unity3d ./snd --save-as ./output

    # Перевести текстовики: сохранить TextAsset, отредактировать, вернуть
    ustudio_cli export -p "Game_Data" --type TextAsset -o ./texts
    ustudio_cli import -p "Game_Data" ./texts --partial --save-as ./output

--------------------------------------------------------------------------------
Android (APK/OBB) и несколько игр в одной папке
--------------------------------------------------------------------------------

APK/OBB загружаются как обычный файл:

    ustudio_cli list -F "game.apk" --type Texture2D --limit 5

Содержимое при первой загрузке один раз распаковывается в кэш
(%LOCALAPPDATA%\UStudio\android_cache); повторные загрузки берут их оттуда.
Обновлённый APK никогда не получит устаревшие данные из кэша; давно не
использованные копии (30 дней) и излишки сверх 4 ГБ удаляются автоматически.
Для управления кэшем используйте команду cache (см. выше).

Сохранить ВНУТРЬ самого APK нельзя: import и save без -A/--save-as завершатся
ошибкой. Используйте -A ПАПКА — в выходной папке будет структура Data/..., которую можно
упаковать обратно в APK.

    ustudio_cli import -F "game.apk" ./edited -A ./output

Несколько игр в одной папке. Одноимённые файлы (level0 и т. п.) различаются по
пути: в ссылке и в -S/--source можно указать папку перед именем файла (регистр не
важен; при неоднозначности вместе с ошибкой будут перечислены все варианты):

    ustudio_cli inspect -p "C:\Games" "GameB/Data/level0:5"
    ustudio_cli list -p "C:\Games" -S "GameB/Data/level0" --type Material

--------------------------------------------------------------------------------
Заставка
--------------------------------------------------------------------------------
При запуске без аргументов (а также при `help` и `shell`) в терминале показывается
логотип UStudio CLI с версией и подсказкой. Заставка идёт в stderr и только когда
stderr — настоящий терминал, поэтому скрипты и вывод `--format json` её не видят.
NO_COLOR=1 отключает цвет, USTUDIO_NO_BANNER=1 — отключает саму заставку. Запуск без
аргументов завершается кодом 2.
