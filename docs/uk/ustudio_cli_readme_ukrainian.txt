================================================================================
UStudio — консольний режим (CLI): довідник
================================================================================

Запуск:
    ustudio_cli <команда> [параметри]

Довідка щодо будь-якої команди:
    ustudio_cli help export
    ustudio_cli export --help

--------------------------------------------------------------------------------
ШВИДКИЙ СТАРТ
--------------------------------------------------------------------------------

    # Відобразити в консолі перші 10 об'єктів AudioClip
    ustudio_cli list -F data.unity3d --type AudioClip --limit 10

    # Експортувати всі текстури гри в папку ./textures
    ustudio_cli export -p "Game_Data" --type Texture2D -o ./textures

    # Вивчити вміст одного об'єкта
    ustudio_cli inspect -F data.unity3d level0:1

    # Експорт -> редагування -> імпорт (зі збереженням результату в ./output)
    ustudio_cli export -F data.unity3d --id level0:1 --mode json -o ./patch
    (відредагуйте файл із ./patch у будь-якому текстовому редакторі)
    ustudio_cli import -F data.unity3d ./patch --save-as ./output

Оригінальні файли при цьому не зачіпаються: --save-as завжди записує в нову папку.

--------------------------------------------------------------------------------
1. ДВА РЕЖИМИ РОБОТИ
--------------------------------------------------------------------------------

Одиночна команда — завантажує дані, виконує одну дію і завершується.
Зручно для скриптів:

    ustudio_cli list -F data.unity3d --type AudioClip

Інтерактивна оболонка (shell) — завантажує дані ОДИН РАЗ, після чого можна
виконувати будь-яку кількість команд без повторного завантаження. Для великих файлів це
помітно швидше: в одиночному режимі завантаження повторюється при кожній команді.

    ustudio_cli shell -F data.unity3d
    ustudio [data.unity3d]> list --type Texture2D --limit 5
    ustudio [data.unity3d]> inspect level0:1 --dump typed
    ustudio [data.unity3d]> exit

В оболонці працюють ті самі команди, але без параметрів завантаження, оскільки дані вже завантажені.
Довідка в оболонці: `help <команда>` (прапорець --help там не використовується).

--------------------------------------------------------------------------------
2. ЗАГАЛЬНІ ПРАВИЛА
--------------------------------------------------------------------------------

ВИВІД
  Результат команди (таблиця, JSON, CSV, дамп об'єкта) йде в stdout — його
  можна перенаправити у файл або передати іншій програмі:
      ustudio_cli list -F data.unity3d --format json > result.json
  Прогрес, попередження та повідомлення про помилки йдуть у stderr і в результат
  не потрапляють. Прапорець -q (--quiet) прибирає індикатор прогресу.
  Якщо вивід перенаправлено (у файл або в іншу програму), він завжди в UTF-8,
  яка б кодова сторінка не була в консолі.
  Прапорець -v (--verbose) вказується ПЕРЕД командою і вмикає подробиці:
  повний текст помилок і примітки генератора SDF-шрифтів:
      ustudio_cli -v import -F data.unity3d ./patch

КОДИ ПОВЕРНЕННЯ
  0 — успіх (зокрема якщо частину об'єктів пропущено з очікуваної причини,
      наприклад порожня текстура під час експорту);
  1 — помилка виконання (нічого не завантажено, об'єкт не знайдено, посилання
      неоднозначне, хоча б одна правка import не застосувалася тощо), текст
      помилки — у stderr (якщо застосувалася лише частина правок і немає --strict,
      решта при цьому зберігається);
  2 — невірні аргументи командного рядка.

ПОСИЛАННЯ НА ОБ'ЄКТ
  PATH_ID унікальний лише всередині одного файлу: один і той самий PATH_ID може
  зустрічатися в багатьох файлах. Тому посилання буває трьох видів:
      1                       — PATH_ID, якщо він є рівно в одному файлі;
      level0:1                — SOURCE:PATH_ID, тобто «файл:PATH_ID»;
      GameB/Data/level0:1     — якщо однойменні файли лежать у різних папках
                                (кілька ігор): додайте частину шляху перед
                                іменем файлу (регістр не важливий).
  Якщо посилання неоднозначне, команда завершиться з помилкою і покаже всі
  відповідні файли — «перший ліпший» вона ніколи не бере.

--------------------------------------------------------------------------------
3. ПАРАМЕТРИ ЗАВАНТАЖЕННЯ
--------------------------------------------------------------------------------

Загальні для команд load, shell, list, inspect, export, import, save.

  -p, --folder ШЛЯХ
      Завантажити папку цілком.
          ustudio_cli list -p "C:\Games\MyGame\MyGame_Data" --type Font
      Гру для macOS завантажуйте, вказавши папку програми (X.app):
          ustudio_cli list -p "MyGame.app" --type Font
      Файли гри Nintendo Switch потрібно спочатку розпакувати іншою програмою, потім вкажіть папку розпакованої гри:
          ustudio_cli list -p "C:\Games\KAMIKO" --type Font

  -F, --files ШЛЯХ
      Завантажити конкретний файл. Можна повторювати: -F level0 -F level1.
      Не можна поєднувати з -p.

  Якщо не вказано ні -p, ні -F
      Команда шукає папку "*_Data" в ПОТОЧНІЙ папці і завантажує її (знайдений
      шлях виводиться у stderr). Папка має містити дані Unity, а не
      просто називатися "*_Data"; якщо відповідних папок немає або їх кілька,
      команда повідомить про це і нічого не вибере сама.
      Там, де команда може перезаписати оригінали (import --in-place, save
      без --save-as, shell), -p або -F є обов'язковими.

  -a, --all
      Завантажити об'єкти ВСІХ типів. Без цього прапорця в списку з'являться 
      лише основні типи (текстури, звуки, шрифти, MonoBehaviour, 
      GameObject тощо); наприклад, об'єктів Transform не буде.

  -x, --exclude ПАПКА
      Пропустити вказану папку під час завантаження папки цілком 
      (можна повторювати кілька разів) — наприклад, щоб виключити із завантаження 
      папку з резервною копією гри всередині ігрової папки.

  --deps ПАПКА
      Додатково шукати залежності в бандлах цієї папки (можна повторювати).
      Стане в пригоді, якщо ви завантажуєте ОДИН бандл через -F, а його скрипти лежать у
      сусідніх бандлах (типово для Unity Addressables, папка
      StreamingAssets/aa/<Платформа>): без --deps імена скриптів будуть
      "Unknown". Папка сканується один раз перед завантаженням (швидко: читаються
      лише заголовки). Під час завантаження папки цілком (-p) сусідні бандли
      знаходяться самі.
          Приклад команди:
          ustudio_cli list -F "aa/StandaloneWindows64/localization_en_assets_all.bundle" --script StringTable --deps "aa/StandaloneWindows64"

  --assembly ПАПКА
      Вказати шлях до папки Managed (яка містить DLL зі скриптами) — за нею 
      визначаються імена та типи полів MonoBehaviour. Зазвичай виявляється сама 
      поруч із папкою *_Data; вкажіть вручну, якщо файли гри лежать окремо або 
      ви збираєтеся підвантажити здамплені за допомогою IL2CppDumper бібліотеки.
          ustudio_cli inspect 179 -F "resources.assets" --assembly "Game_Data/Managed"

  -u, --fallback-version ВЕРСІЯ
      Вказати версію Unity, яка буде використана, якщо у файлі вона не прописана
      або розробник спеціально спотворив шапку ігрових файлів.
      Приклад введення: "2019.4.15f1"

  -k, --cn-key КЛЮЧ
      Вказати 16-байтний ключ дешифрування AssetBundle для ігор, створених на 
      китайському рушії Unity. Без брутфорсу.

  -T, --threshold ЧИСЛО   (за замовчуванням 2000000 <об'єктів>)
      Поріг спрацьовування попередження
  -L, --large continue
      Якщо в завантажуваних даних більше об'єктів, ніж поріг, потрібне підтвердження.
      В одиночному режимі підтвердження дає прапорець -L continue (без нього команда
      завершиться з помилкою, а не чекатиме введення); у shell буде поставлено запитання
      "продовжити? y/n". Без -a при цьому завантажуються лише основні типи;
      решта об'єктів не читаються і під час збереження записуються без змін.
          ustudio_cli export -p "Game_Data" --type AudioClip -L continue

  -c, --collision {keep_first,raise}   (за замовчуванням keep_first)
      Що робити з файлами, що мають однакові імена (наприклад, два
      resources.assets у папці з кількома іграми). Усі такі файли
      завантажуються в будь-якому разі; ресурси та посилання між файлами беруть найближчий
      до об'єкта файл. Параметр впливає лише на пошук файлу ВИКЛЮЧНО за іменем
      (наприклад "level0" без вказання гри):
        keep_first — береться перший знайдений (за замовчуванням);
        raise      — перервати завантаження при першому збігу імен.

  -q, --quiet
      Не показувати індикатор прогресу.

--------------------------------------------------------------------------------
4. КОМАНДИ
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
load — завантажити і завершитися
--------------------------------------------------------------------------------
Застосовуються лише параметри завантаження. Зручно, щоб перевірити, що папка 
завантажується.

    ustudio_cli load -p "Truck-kun_Data" --all

--------------------------------------------------------------------------------
shell — завантажити один раз і працювати інтерактивно
--------------------------------------------------------------------------------
Параметри завантаження, потім запрошення "ustudio [ім'я]>". Вихід — exit або quit.

    ustudio_cli shell -p "Game_Data" --fallback-version 2021.3.0f1

--------------------------------------------------------------------------------
list — відобразити список об'єктів
--------------------------------------------------------------------------------
Параметри завантаження плюс:

  -t, --type ТИПИ          Типи через кому: "Texture2D" або
                            "Texture2D,AudioClip".
  -s, --script ІМ'Я         m_ClassName скрипта (для MonoBehaviour).
                            Знаходить ВСІ скрипти з таким іменем; для конкретики 
                            вкажіть у форматі "m_Namespace.m_ClassName".
  -n, --name-contains СТР  Підрядок в імені об'єкта (без урахування регістру).
  -S, --source ІМ'Я         Точне ім'я файлу (або запису бандла), наприклад
                            "level0" або "sharedassets0.assets".
  -m, --modified           Відобразити лише об'єкти з незбереженими правками.
  -r, --sort КОЛОНКИ       Задати параметри сортування (див. нижче).
  -f, --format {table,json,csv}   Формат виводу (за замовчуванням table).
  -l, --limit ЧИСЛО        Обмеження на кількість виведених у консолі рядків.
  -o, --out ФАЙЛ           Записати результат у файл замість виводу на екран.
  --sdf                    Показати SDF-шрифти (див. нижче).

Сортування -r/--sort. Колонки: path_id, name, type, script_name, source, size,
modified. За замовчуванням — сортування за зростанням; "-" перед іменем колонки — за
спаданням. Колонки через кому задають пріоритет (усередині рівних значень першої
колонки працює друга). Рядки порівнюються без урахування регістру.
ВАЖЛИВО: значення, що починається з "-", пишіть через "=": --sort=-size
(а не --sort -size, інакше "-size" буде прийнято за окремий прапорець).

SDF-шрифти (--sdf). Відображає шрифти TextMeshPro (TMP_FontAsset) разом з їхнім
матеріалом, текстурою-атласом та вихідним файлом шрифту. Фільтри -t/-s/-n/-S/-m/
-r при цьому не працюють, а -f/-l/-o працюють. У таблиці в заголовку кожного
шрифту в квадратних дужках вказано посилання SOURCE:PATH_ID — його потрібно передавати
в `export --sdf --id`. Якщо матеріал або текстуру не визначено, замість них
виводиться причина.

Приклади:
    ustudio_cli list -F data.unity3d --type AudioClip --limit 10
    ustudio_cli list -F data.unity3d --script "PlayerController" --format json
    ustudio_cli list -F data.unity3d --name-contains "button" --type Sprite
    ustudio_cli list -F data.unity3d --modified

    # Зберегти список об'єктів у CSV-файл:
    ustudio_cli list -p "Game_Data" --type Texture2D --format csv -o textures.csv

    # Відобразити список об'єктів із сортуванням за іменами від А до Я:
    ustudio_cli list -F data.unity3d --sort name

    # Відобразити об'єкти із сортуванням за іменами від Я до А (зверніть 
    увагу на символ "="):
    ustudio_cli list -F data.unity3d --sort=-name

    # Сортування спочатку за типом (А-Я), всередині типу — за розміром (від більшого до 
    меншого):
    ustudio_cli list -F data.unity3d --sort=type,-size

    # Відобразити список усіх SDF-шрифтів:
    ustudio_cli list -F data.unity3d --sdf

--------------------------------------------------------------------------------
inspect — вивчити вміст одного об'єкта
--------------------------------------------------------------------------------
Параметри завантаження плюс:

  ref                      Посилання на об'єкт: PATH_ID або SOURCE:PATH_ID.
  -S, --source ІМ'Я         Файл, якщо PATH_ID є в кількох архівах Unity 
                           (замість вказання файлу через двокрапку в ref).
  -d, --dump {typed,json,hex}   Формат відображення дампа (за замовчуванням typed)
        typed — «Type Name = value», по рядку на поле;
        json  — дамп у форматі JSON;
        hex   — перші 4096 байт даних об'єкта в шістнадцятковому вигляді.

Приклади:
    ustudio_cli inspect -F data.unity3d level0:1
    ustudio_cli inspect -F data.unity3d level0:1 --dump json
    ustudio_cli inspect -F data.unity3d 1 --source level0

    # Якщо PATH_ID є в кількох файлах, команда покаже всі варіанти:
    ustudio_cli inspect -F data.unity3d 1
      -> помилка: PATH_ID 1 є в кількох файлах, уточніть source:path_id

--------------------------------------------------------------------------------
export — експорт об'єктів у папку
--------------------------------------------------------------------------------
Параметри завантаження, фільтри з list (-t/-s/-n/-S) плюс:

  -i, --id ПОСИЛАННЯ   Експортувати рівно один об'єкт за айді (замість фільтрів).
  -m, --mode {typed,raw,content-raw,json}   Режим експорту (за замовчуванням typed)
        typed        — звичайний формат об'єкта: PNG для текстур, WAV для звуку,
                       шрифт, текст тощо; якщо тип не підтримує конвертацію,
                       він експортується як JSON-дамп;
        json         — повний дамп полів (розширення — .dump.json);
        raw          — сирі байти об'єкта (розширення — .dump.bin);
        content-raw  — сирі байти необроблених даних об'єкта у зовнішньому ресурсі 
                       (наприклад, пікселі текстури з .resS)
                       (розширення — .resdata.bin).
  -o, --out ПАПКА      Куди зберігати (за замовчуванням ./UStudio_Assets).
  -w, --overwrite      Перезаписувати існуючі файли.
  --strict             Повернути ненульовий код, якщо хоч один об'єкт не вдалося
                       експортувати (очікувані пропуски — порожня текстура,
                       звук без даних — помилкою не вважаються).
  --group-by {none,type,source}
        Розкладати файли по підпапках усередині -o: none — все в одну папку (за
        замовчуванням), type — за типами (-o/Texture2D/), source — за файлами-
        джерелами. Значення за замовчуванням можна зберегти: `config set
        export_grouping type`.
  --sdf                Експортувати SDF-шрифти цілком (MonoBehaviour,
                       матеріал, текстура і, якщо є, референсний Font) за шляхом  
                       SDF/<ім'я_шрифту>/ всередині папки -o. При вказанні параметра
                       -i — експортувати один SDF-шрифт (потрібне посилання на
                       TMP_FontAsset; посилання беріть із результату виводу команди 
                       `list --sdf`), без вказання -i — експортувати всі 
                       знайдені SDF-шрифти. Фільтри та параметр -m при цьому не 
                       діють. Компонент, який не вдалося визначити, 
                       пропускається з повідомленням, решта експортується.

Імена файлів мають вигляд "{ім'я} #{path_id} ({source}).розширення" — за ними
команда import потім знаходить потрібний об'єкт. Не перейменовуйте файли.

Приклади:
    ustudio_cli export -F data.unity3d --type Texture2D -o ./textures
    ustudio_cli export -p "Game_Data" --type AudioClip --group-by source -o ./audio
    ustudio_cli export -F data.unity3d --id level0:1 --mode json -o ./dump
    ustudio_cli export -F data.unity3d --name-contains "logo" --type Texture2D,Sprite

    # Експорт одного SDF-шрифту (з вказанням посилання на TMP_FontAsset із `list --sdf`):
    ustudio_cli export -F data.unity3d --sdf --id "sharedassets0.assets:2646" -o ./out

    # Експорт усіх SDF-шрифтів за шляхом SDF/<ім'я шрифту>/:
    ustudio_cli export -F data.unity3d --sdf -o ./out

--------------------------------------------------------------------------------
import — застосувати папку з патчами
--------------------------------------------------------------------------------
Бере файли з папки, знаходить за іменем відповідні об'єкти і замінює їхній
вміст. Імена файлів мають бути такими ж, як при експорті:
"{ім'я} #{path_id} ({source}).розширення". Формат правки визначається
розширенням:

    .dump.json     — поля об'єкта цілком (JSON-дамп);
    .dump.bin      — сирі байти об'єкта (Raw-дамп);
    .resdata.bin   — сирі байти зовнішнього ресурсу об'єкта (Raw Content);
    .png           — картинка для Texture2D / Sprite;
    .wav           — звук для AudioClip;
    .mp4 / .webm   — відео для VideoClip;
    .ttf / .otf    — шрифт для Font;
    .txt / .json / .bin — вміст TextAsset.

Якщо для одного об'єкта в папці лежить кілька файлів, вони застосовуються в
порядку .dump.bin -> .dump.json -> .resdata.bin -> .png/.wav/... — тобто
відредагований PNG або WAV перемагає «старі» дампи.

Патч, для якого в завантажених файлах немає об'єкта, мовчки не зникає. Так
буває після оновлення гри, коли номери об'єктів змістилися. Команда пише
по рядку на кожен такий файл:

    unmatched: Ім'я #12345 (sharedassets1.assets).dump.bin: no object #12345 in 'sharedassets1.assets'
    1 patch file(s) matched no loaded object and will NOT be applied (...)

і підраховує їх у підсумку: «Applied 2/3 patch(es)» і «1 unmatched». Решта
патчів при цьому застосовуються. Якщо жоден файл не знайшов об'єкт, команда
завершується з помилкою. Зі --strict при будь-якому такому файлі не застосовується і не
зберігається нічого (код повернення не нуль). У `--dry-run` рядок
«DRY RUN - N match(es) would be applied» підраховує лише знайдені патчі.

Знайдений об'єкт звіряється з патчем за іменем з імені файлу. У MonoBehaviour
порівнюються і скрипт, і ім'я («Скрипт.Ім'я»): після оновлення гри на старому
номері часто опиняється сусідній об'єкт із тим самим скриптом. Якщо ім'я інше,
правка все одно вважається своєю, коли це видно з самого дампа (.dump.json):
у об'єкта те ім'я, яке дала йому ця ж правка (мод уже ставився), або той самий
GameObject. У об'єкта без імені («Скрипт.Unnamed») звіряти нічого: така правка
пропускається, якщо сусідні за номером правки того ж файлу вже не збігаються зі
своїми об'єктами (номери у файлі змістилися). Пропущені правки виводяться
рядком «skipped: …» із причиною; --force застосовує їх усе одно.

Якщо патч знайшов свій об'єкт, але застосувати його не вдалося (файл пошкоджено,
дані не підходять до об'єкта, помилка кодування), решта патчів усе одно
застосовуються і зберігаються. Наприкінці команда повідомляє, скільки правок не
застосувалося, і завершується з кодом 1 (те, що застосувалося, вже збережено). Те
саме стосується SDF-шрифтів із sdf_map.txt, які не вдалося створити.
Потрібно «все або нічого» (скрипти, інсталятори модів)? Додайте --strict: при
будь-якому збої не застосовується і не зберігається нічого.
Виняток, у тому числі для --strict: дані зовнішніх ресурсів AudioClip /
VideoClip (режим --res-mode original) записуються у файл .resource / .resS
одразу, ще до збереження. Якщо імпорт скасовано, такі файли вже змінено;
повідомлення про помилку перераховує їх, а з --backup їхній початковий вміст
збережено в резервній копії.

Для .dump.bin перевіряється, що дані взагалі можуть бути цим об'єктом: файл не
порожній, не обрізаний, його структура збігається зі структурою об'єкта, а в
MonoBehaviour посилання на скрипт таке ж, як у об'єкта зараз (інакше правка зроблена
для іншого скрипта або для іншої версії гри). Повна перевірка структуры
можлива, коли скрипти гри читаються (при завантаженні всієї папки); з --partial
перевіряється лише посилання на скрипт.

Параметри завантаження плюс:

  ПАПКА                Папка з патч-файлами (обов'язковий аргумент). Перевіряється ДО
                       завантаження: якщо в ній немає відповідних файлів, команда
                       одразу завершиться з помилкою.
  -d, --dry-run        Показати, що буде застосовано, нічого не змінюючи.
  --strict             «Все або нічого» для скриптів та інсталяторів. Якщо хоч одна
                       правка не застосувалася, патч-файл не знайшов свій об'єкт
                       (див. «unmatched» вище), правка пропущена через розбіжність
                       імені чи скрипта або ціль sdf_map.txt не знайшла об'єкта,
                       команда завершується з кодом 1 і нічого не застосовує і не
                       зберігає. Без --strict застосовується все, що можливо, а
                       збої лише перераховуються.
  --force              Застосовувати і ті правки, у яких ім'я або скрипт в імені
                       файлу вже не збігається з об'єктом (наприклад, після
                       оновлення гри PATH_ID міг перейти до іншого об'єкта).
                       За замовчуванням такі правки пропускаються.
  --partial            Завантажити не всю папку з -p, а лише файли, які
                       прописані в іменах імпортованих патч-файлів. Це підвищить
                       швидкість імпорту у великих папках. Працює тільки в
                       режимі одиночних команд і тільки з параметром -p. Якщо 
                       якийсь файл не можна визначити однозначно (його або немає, 
                       або є кілька з однаковими іменами — допоможе 
                       параметр -x), команда повідомить причину і завантажить 
                       папку цілком. Скрипти гри при такому імпорті не
                       читаються, тому у MonoBehaviour правка не
                       звіряється за іменем скрипта (рядок «script
                       unresolved»); .dump.bin звіряється тільки за посиланням
                       на скрипт.

  Текстури:
  --tex-mode {match_original,manual}
        match_original — зберегти формат текстури як є (за замовчуванням);
        manual         — задати формат через --tex-format.
  --tex-format ФОРМАТ  Формат для --tex-mode manual:
        без стиснення:              RGBA32 (з альфою), RGB24, Alpha8
        десктоп/консолі (BC/DXT):  DXT1 (без альфи), DXT3, DXT5, BC4, BC5, BC7
                                   (краща якість; тільки для Unity 5 і новіше)
        мобільні ігри:            ETC_RGB4, ETC2_RGB, ETC2_RGBA8, ASTC_RGBA_4x4 (якість
                                   вища), ASTC_RGBA_8x8 (розмір менший), ATC_RGB4, ATC_RGBA8
        Формат застосовується, навіть якщо не підходить цільовій платформі гри (наприклад,
        DXT у мобільній грі). Назву формату пишіть точно як у списку, з урахуванням регістру.
        Одрукарська помилка НЕ викликає помилку, формат текстури просто залишиться колишнім.
  --tex-quality {medium,high}   Більше ні на що не впливає: текстури завжди стискаються з найкращою
                                якістю. залишений, щоб старі команди працювали.

  Звук:
  --audio-quality ЧИСЛО    Якість кодування, 0–100 (0 — звичайна, 100 —
                           найкраща).

  Куди писати дані AudioClip / VideoClip (та інших об'єктів із зовнішнім
  ресурсом):
  --res-mode {original,custom_resource}
        original        — у вихідний ресурс об'єкта (за замовчуванням);
        custom_resource — в окремий файл-ресурс поруч (ім'я задається — через
                          --res-name), щоб вихідний ресурс не зростав при кожному
                          імпорті.
  --res-name ІМ'Я       Ім'я окремого файлу-ресурсу (тільки з --res-mode custom_resource).
                       Файл з'явиться на диску після збереження.

  Відео:
  --transcode                          Перекодувати відео перед пакуванням (за замовчуванням
                                       вимкнено: файл кладеться як є).
  --transcode-to {original,h264,vp8}   Цільовий формат; original — як у
                                       вихідного кліпу (з відкатом до h264, видавши
                                       попередження).
  --transcode-quality ЧИСЛО   Якість конвертації від 0 до 100. 
                              Результат конвертації створюється поруч із
                              патч-файлом і має суфікс "_transcoded".

  Значення за замовчуванням для всіх цих параметрів зберігаються в `config` (див.
  нижче), тож один раз налаштувавши їх, можна не вказувати щоразу.

  Збереження результату:
  Правки застосовуються тільки в пам'яті процесу, тому в одиночному режимі без
  прапорців нижче результат автоматично зберігається в НОВУ папку
  ./UStudio_Packed (оригінали не зачіпаються):
  -A, --save-as ПАПКА  Зберегти в цю ОКРЕМУ папку.
  --in-place           Перезаписати оригінальні файли (папку гри потрібно вказати
                       явно через -p або -F).
  -b, --backup         Перед перезаписом створити резервну копію оригіналів
                      (нова копія створюється при кожному збереженні). Якщо
                       не вдасться (наприклад, немає місця на диску), оригінали не
                       будуть зачеплені. 
                       У копію потрапляють тільки файли, які імпорт
                       дійсно змінює: змінюваний файл (.assets, архів)
                       і ті .resource / .resS, у які імпорт записав
                       дані (вони записуються одразу, до збереження).
                       Решта файлів-ресурсів не копіюються. Копія кожного
                       файлу — це його вміст до першого запису.
                       З --save-as копія не робиться (нічого не
                       перезаписується): команда попередить про це.
  --backup-dir ПАПКА   Кудикласти копії (вмикає --backup): сюди потрапляють і
                       копії архівів, і копії файлів-ресурсів. За замовчуванням —
                       %LOCALAPPDATA%\UStudio\backups, поза папкою гри, щоб
                       копії не потрапляли в наступне завантаження.
  --backup-keep N      Скільки останніх копій кожного файлу зберігати крім
                       найпершої (за замовчуванням 1). Перша копія — недоторканий
                       оригінал — зберігається завжди; зайві проміжні
                       видаляються, щоб копії не накопичувалися.
  У shell автозбереження немає — сеанс триває, і зберегти можна пізніше
  командою save.

  Ігри на Addressables (папка StreamingAssets\aa): у каталозі гри
  (catalog.json, catalog.bin або catalog.bundle) у бандла може бути
  записана контрольна сума. Якщо вона є, гра не завантажить змінений
  бандл зі старою сумою. Тому при збереженні такого бандла каталог
  оновлюється автоматично: з --in-place він перезаписується разом із
  бандлами (і потрапляє в резервну копію), з --save-as кладеться в ту ж
  папку поруч із копіями. Копіюючи результат у гру, копіюйте і каталог.

Приклади:
    # Подивитися, що буде застосовано, нічого не змінюючи:
    ustudio_cli import -F data.unity3d ./edited --dry-run

    # Застосувати і зберегти в нову папку:
    ustudio_cli import -F data.unity3d ./edited --save-as ./output

    # Застосувати і перезаписати оригинал, зробивши резервну копію:
    ustudio_cli import -F data.unity3d ./edited --in-place --backup

    # Імпорт у великій папці: завантажити тільки потрібні файли
    ustudio_cli import -p "Game_Data" ./edited --partial --save-as ./output

    # Текстури: перекодувати в BC7
    ustudio_cli import -F data.unity3d ./textures --tex-mode manual --tex-format BC7 --save-as ./output

    # Імпорт аудіо з високою якістю, запис даних — в окремий файл-ресурс
    ustudio_cli import -F data.unity3d ./audio --audio-quality 90 --res-mode custom_resource --res-name my_audio.resource --save-as ./output

    # Пропускати «сумнівні» правки (за замовчуванням) або все ж таки застосувати їх
    ustudio_cli import -F data.unity3d ./edited --dry-run
    ustudio_cli import -F data.unity3d ./edited --force --save-as ./output


--------------------------------------------------------------------------------
save — зберегти змінені файли на диск
--------------------------------------------------------------------------------
Параметри завантаження плюс:

  -A, --save-as ПАПКА  Зберегти в НОВУ папку (оригінали не будуть зачеплені). Без
                       цього прапорця оригінали перезаписуються.
  -d, --dry-run        Показати, що було б записано, нічого не записуючи.
  -b, --backup, --backup-dir ПАПКА, --backup-keep N
                       Заздалегідь створювати резервні копії оригіналів — так само, 
                       як у команди import.

Якщо змінених об'єктів немає, команда завершиться з помилкою ("nothing modified").
В одиночному режимі об'єкти патчаться за допомогою команди import, тому
окрема команда save частіше потрібна в shell:

    ustudio [data.unity3d]> import ./edited
    ustudio [data.unity3d]> list --modified
    ustudio [data.unity3d]> save --save-as ./output

Після перезапису оригіналів на місці (без --save-as) завантажені файли
закриваються, і для продовження роботи в shell потрібно завантажити дані заново.

--------------------------------------------------------------------------------
Генерація SDF-шрифтів (файл sdf_map.txt) — ЕКСПЕРИМЕНТАЛЬНО
--------------------------------------------------------------------------------
Окремої команди немає: якщо в папці правок для import (у тому числі у вкладених
папках) лежить файл sdf_map.txt, то після звичайних правок import створює для
описаних у ньому шрифтів TextMeshPro (TMP_FontAsset) нові гліфи з вказаного
.ttf/.otf. Звичайних файлів правок у цій папці не потрібно — достатньо
sdf_map.txt та шрифтів.

Функція експериментальна: перед перезаписом оригіналів перевірте результат
через --dry-run та/або --save-as у тимчасову папку.

    ustudio_cli import -F data.unity3d ./sdf_patches --dry-run
    ustudio_cli import -F data.unity3d ./sdf_patches --save-as ./output

--dry-run виводить план ("SDF <посилання> 'ім'я' <- шрифт (mode=..., size=...,
range=..., N chars)"), нічого не генеруючи. Під час роботи для кожного шрифту
виводиться один рядок:
    [1/2] ok: resources.assets:539 'LiberationSans SDF': added 182/183
Для відображення приміток генератора потрібен прапорець -v.

Детальний опис формату sdf_map.txt (усі налаштування, як записувати символи, приклади)
лежить у файлі sdf_map.md. Тут же лише те, що стосується запуску з командного рядка. 

Короткий приклад sdf_map.txt:
    "Arial SDF", "Other SDF" = font.ttf
    "Pixel SDF" = pixel.ttf, mode=full, size=fit, chars="ABCabc"

Звідки беруться символи (за порядком): chars= у рядку -> chars= у рядку
"default:" -> файл chars.txt поруч із sdf_map.txt. Якщо немає жодного — видається помилка з
указанням рядка.

Рядок "default:" (не більше одного, у будь-якому місці) задає значення для всіх рядків,
де вони не вказані. size, match_height, range, atlas та add_chars з нього
застосовуються тільки до рядків з підсумковим режимом full.
Буде вважатися за помилку тільки якщо ці налаштування написані прямо в рядку з 
режимом add/replace. Порядок пріоритету: рядок шрифту -> "default:" -> вбудовані значення
(mode=add, розмір і чіткість як у самого шрифту, match_height=on, add_chars=on).

Відносні шляхи (шрифт, файл символів) відраховуються від папки sdf_map.txt,
тому карту зі шрифтами можна переносити однією папкою.

Один і той самий шрифт у двох рядках з різними налаштуваннями — завжди видається помилка
з перерахуванням усіх конфліктів. Ціль, яка нічого не знайшла, дає
попередження (зі --strict — помилку). Параметр --partial у поєднанні з sdf_map.txt
завантажує всю папку цілком (оскільки карта може містити імена SDF, які знаходяться
невідомо в якому файлі).

--------------------------------------------------------------------------------
cab — робота з одним архівом Unity напряму
--------------------------------------------------------------------------------
Команда cab не використовує параметри завантаження: у кожної підкоманди свій прапорець
-b/--bundle (в одиночному режимі) або спочатку виконується `cab open` (у shell).

  cab open ШЛЯХ
      Відкрити бандл. У shell після цього можна викликати list/view/export/rebuild
      без вказання бандла.

  cab list [-b БАНДЛ] [-f {table,json}] [-l ЧИСЛО]
      Відобразити внутрішні записи бандла: ім'я, розмір, кількість об'єктів.

  cab view [-b БАНДЛ] -e ЗАПИС
      Розібрати один запис і показати його об'єкти MonoBehaviour таблицею.

  cab export [-b БАНДЛ] [-e ЗАПИС] [-o ПАПКА] [-q]
      Зберегти один запис (сирі байти) або, якщо -e не вказано, ВСІ записи
      бандла. -o за замовчуванням ./UStudio_Assets.

  cab rebuild [-b БАНДЛ] -o ФАЙЛ [--from-folder ПАПКА] [--set ЗАПИС=ШЛЯХ ...]
              [--mode {memory,disk}] [--packer {none,lz4,lz4hc,lzma,original}] [-q]
      Зібрати бандл наново, підставивши нові файли замість вказаних записів
      (бандл завжди збирається цілком — так влаштований формат):
        --from-folder ПАПКА — зіставити файли в папці із записами за іменем
                              файлу;
        --set ЗАПИС=ШЛЯХ   — замінити один запис (можна повторювати; застосовується
                              після --from-folder і може перевизначити його);
        --mode disk         — перезібрати на фізичному накопичувачі, використовується 
                              за замовчуванням: збирання можна перервати (Ctrl+C);
        --mode memory       — перезібрати в пам'яті. Швидше, але перервати збирання не можна;
        --packer            — метод стиснення (original — як у вихідного бандла).

Приклади:
    ustudio_cli cab list --bundle data.unity3d --limit 10
    ustudio_cli cab view --bundle data.unity3d --entry level0
    ustudio_cli cab export --bundle data.unity3d --entry level0 -o ./out
    ustudio_cli cab export --bundle data.unity3d -o ./all_entries
    ustudio_cli cab rebuild --bundle data.unity3d --set level0=./new_level0 -o ./rebuilt.unity3d
    ustudio_cli cab rebuild --bundle data.unity3d --from-folder ./edited_entries -o ./rebuilt.unity3d --packer lz4

--------------------------------------------------------------------------------
backup — створити резервні копії оригіналів
--------------------------------------------------------------------------------
Копії створюються прапорцем --backup (або --backup-dir) при перезаписі оригіналів
(save, import --in-place). Команди нижче гру не завантажують.

  backup list [--game ІМ'Я] [--backup-dir ПАПКА]
      Відобразити всі створені копії: папка, дата, файли, розмір і загальний обсяг. 
      У квадратних дужках перераховуються гра та її версія на момент створення бекапу, 
      якщо вдалося визначити. Параметр --game залишає у виводі бекапи однієї 
      конкретної гри (вводиться частина назви, без урахування регістру); точні
      назви ігор для параметра --game ви можете подивитися у виводі `backup list`.

  backup restore [ПАПКА_КОПІЇ] [-f ІМ'Я]... [--copy ДАТА] [--game ІМ'Я] [-d]
                 [--relocate СТАРА=НОВА]... [--backup-dir ПАПКА]
      Повертає файли на їхні колишні місця. Без вказання ПАПКА_КОПІЇ для кожного файлу
      береться найСТАРІША копія — недоторканий оригінал; з ПАПКА_КОПІЇ —
      файли тільки цієї копії.
        -f, --file ІМ'Я   відновити тільки цей файл (ім'я або повний шлях;
                         можна повторювати);
        --copy ДАТА      брати не найстарішу, а найновішу копію, зроблену в
                         цей час ("2026-09-24" або "2026-09-24 19:32");
        --game ІМ'Я       відновити тільки копії конкретної гри;
        -d, --dry-run    показати, що буде відновлено, нічого не змінюючи;
        --relocate СТАРА=НОВА
                         гру перенесли: відновлювати в папку НОВА замість
                         СТАРА (СТАРА — шлях так, як його показує
                         `backup list`; можна повторювати).
      Перед заміною поточні файли самі копіюються в нову резервну копію —
      щоб відновлення теж можна було скасувати в подальшому. Файл 
      записується поруч і підміняється цілком, тому збій не залишить напів
      записаний файл; файл, зайнятий іншою програмою, видасть помилку.

      Файл, чия папка більше не існує (наприклад, гру перенесли),
      не відновлюється: команда нічого не змінює і підказує про
      --relocate. Стара папка заново не створюється, щоб файл не опинився не там,
      де гра лежить зараз.

      Якщо коротке ім'я (-f resources.assets) є в копіях кількох ігор, команда
      відмовиться вгадувати і покаже доступні варіанти: вкажіть повний шлях до файлу або
      додайте --game.

      ВАЖЛИВО: копія — це файл на момент резервування. Якщо гра після цього
      автоматично оновиться, оригінал у резервній копії вже буде неактуальним.
      Відрізнити оновлення гри від ваших правок неможливо. Ви також можете перевірити 
      версію гри резервних копій, викликавши команду `backup list`.

Приклади:
    # Відобразити всі копії та їхню вагу:
    ustudio_cli backup list

    # Відобразити копії однієї конкретної гри:
    ustudio_cli backup list --game Petscop

    # Зробити копію при перезаписі, потім за потреби повернути оригінали:
    ustudio_cli import -F data.unity3d ./edited --in-place --backup
    ustudio_cli backup restore

    # Спочатку подивитися, що буде відновлено:
    ustudio_cli backup restore --dry-run

    # Відновити один файл за іменем:
    ustudio_cli backup restore -f resources.assets

    # Відновити резервну копію для файлу resources.assets, 
    # зроблену в певний день:
    ustudio_cli backup restore -f resources.assets --copy 2026-09-24

    # Якщо файл із таким іменем є у кількох ігор — вказати гру або шлях:
    ustudio_cli backup restore -f resources.assets --game Petscop
    ustudio_cli backup restore -f "C:\Games\Petscop\Petscop_Data\resources.assets"

    # Повернути всі копії однієї гри:
    ustudio_cli backup restore --game Petscop

    # Гру перенесли в іншу папку: вказати, куди відновлювати:
    ustudio_cli backup restore --relocate "C:\Games\Petscop=D:\Games\Petscop"

    # Відновити конкретну копію (папка взята з виводу `backup list`):
    ustudio_cli backup restore "C:\Users\me\AppData\Local\UStudio\backups\2026-09-24_19-32-01"

5. НАСКРІЗНИЙ ПРИКЛАД: експорт -> редагування -> імпорт -> перевірка
--------------------------------------------------------------------------------

    # 1. Експортувати об'єкт у JSON:
    ustudio_cli export -F data.unity3d --id level0:1 --mode json -o ./patch

    # 2. Відредагувати ./patch/logo #1 (level0).dump.json у будь-якому текстовому
    #    редакторі — наприклад, змінити значення "m_Name".

    # 3. Застосувати правку і зберегти результат у нову папку:
    ustudio_cli import -F data.unity3d ./patch --save-as ./output

    # 4. Перевірити результат, вивчивши вміст об'єкта в пропатченому файлі:
    ustudio_cli inspect -F ./output/data.unity3d level0:1 --dump json

Оригінальний data.unity3d не змінився. Щоб перезаписати оригінал, використовуйте
--in-place (краще спільно з параметром --backup).

Той самий сценарій в інтерактивному середовищі — без повторного завантаження на кожному кроці:

    ustudio_cli shell -F data.unity3d

    ustudio [data.unity3d]> export --id level0:1 --mode json -o ./patch
    (файл редагується поза оболонкою)
    ustudio [data.unity3d]> import ./patch
    ustudio [data.unity3d]> list --modified
    ustudio [data.unity3d]> save --save-as ./output
    ustudio [data.unity3d]> exit

Інші типові сценарії:

    # Замінити текстуру: експорт -> редагування PNG -> імпорт
    ustudio_cli export -F data.unity3d --name-contains "logo" --type Texture2D -o ./tex
    (відредагуйте PNG, не змінюючи ім'я файлу)
    ustudio_cli import -F data.unity3d ./tex --save-as ./output

    # Замінити звук
    ustudio_cli export -F data.unity3d --type AudioClip --name-contains "click" -o ./snd
    (замініть WAV своїм файлом, не змінюючи ім'я)
    ustudio_cli import -F data.unity3d ./snd --save-as ./output

    # Перекласти текстовики: зберегти TextAsset, відредагувати, повернути
    ustudio_cli export -p "Game_Data" --type TextAsset -o ./texts
    ustudio_cli import -p "Game_Data" ./texts --partial --save-as ./output

--------------------------------------------------------------------------------
Android (APK/OBB) і кілька ігор в одній папці
--------------------------------------------------------------------------------

APK/OBB завантажуються як звичайний файл:

    ustudio_cli list -F "game.apk" --type Texture2D --limit 5

Вміст при першому завантаженні один раз розпаковується в кеш
(%LOCALAPPDATA%\UStudio\android_cache); повторні завантаження беруть його звідти.
Оновлений APK ніколи не отримає застарілі дані з кешу; давно не
використовувані копії (30 днів) та залишки понад 4 ГБ видаляються автоматично.
Для керування кешем використовуйте команду cache (див. вище).

Зберегти ВСЕРЕДИНУ самого APK неможливо: import і save без -A/--save-as завершаться
помилкою. Використовуйте -A ПАПКА — у вихідній папці буде структура Data/..., яку можна
упакувати назад в APK.

    ustudio_cli import -F "game.apk" ./edited -A ./output

Кілька ігор в одній папці. Однойменні файли (level0 тощо) відрізняються за
шляхом: у посиланні та в -S/--source можна вказати папку перед іменем файлу (регістр не
важливий; при неоднозначності разом із помилкою будуть перераховані всі варіанти):

    ustudio_cli inspect -p "C:\Games" "GameB/Data/level0:5"
    ustudio_cli list -p "C:\Games" -S "GameB/Data/level0" --type Material

--------------------------------------------------------------------------------
Заставка
--------------------------------------------------------------------------------
При запуску без аргументів (а також при `help` і `shell`) у терміналі показується
логотип UStudio CLI з версією та підказкою. Заставка йде в stderr і тільки коли
stderr — справжній термінал, тому скрипти та вивід `--format json` її не бачать.
NO_COLOR=1 вимикає колір, USTUDIO_NO_BANNER=1 — вимикає саму заставку. Запуск без
аргументів завершується кодом 2.
